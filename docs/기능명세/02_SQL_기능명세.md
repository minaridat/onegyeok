## 2. 와이어프레임

### S13. SQL DB 클라이언트 탭

```
┌───────────────────────────────────────────────────┐
│ [mysql-test ●연결됨]  [mysql-test #2]        [+]    │
├───────────────────────────────────────────────────┤
│ MySQL / MariaDB · 127.0.0.1:3307 / testdb           │
├───────────────────────────────────────────────────┤
│ 실행 ▶  ⌘/Ctrl+Enter          12행 · 8ms             │
├───────────────────────────────────────────────────┤
│ SELECT * FROM users ORDER BY id                      │
│                                                       │
├───────────────────────────────────────────────────┤
│ id │ name                                             │
│ 1  │ alice                                             │
│ 2  │ bob                                               │
└───────────────────────────────────────────────────┘
```

- 서버 등록 시 프로토콜을 "SQL"로 선택하면 DB 엔진(MySQL/MariaDB, PostgreSQL, MS SQL Server)과 데이터베이스명(선택)을 추가로 입력한다
- 접속 시 비밀번호는 SSH와 동일하게 저장하지 않는다 — 탭 안의 접속 폼에 그때그때 직접 입력(사용자명을 등록 시 비워뒀다면 사용자명도 함께 입력)
- 접속에 성공하면 쿼리 에디터 + 결과 테이블 화면으로 전환되며, 쿼리를 실행하면 컬럼/행/소요시간이 표시된다
- 에디터에서 선택한 영역이 있으면 해당 SQL만 실행하며, 선택하지 않으면 전체 내용을 실행한다
- PostgreSQL/MS SQL Server에서 여러 결과가 반환되면 결과 선택 메뉴로 전환한다. MySQL은 한 번에 한 SQL문을 실행한다(다중 statement 옵션은 활성화하지 않음)
- 같은 서버를 여러 번 클릭하면 SSH와 동일하게(01_SSH F-216) 매번 새 탭·새 연결이 열린다
- 인증 실패 시 접속 폼에 인라인 에러가 표시되고 그 자리에서 비밀번호를 다시 입력할 수 있다(SSH의 "재시도" 경험과 동일한 원칙)

## 3. 기능 명세 (F-1201 ~ F-1206)

| ID | 요구사항 | 비고 |
|---|---|---|
| F-1201 | 서버 등록 시 프로토콜로 "SQL"을 선택하면 DB 엔진(MySQL/MariaDB, PostgreSQL, MS SQL Server)과 데이터베이스명(선택)을 입력할 수 있다 | S13. `src/main/db-manager.js`의 엔진별 어댑터로 구현 — 구현 완료 |
| F-1202 | SQL 서버를 클릭하면 탭에 접속 폼(사용자명(선택)·비밀번호)이 표시되고, 비밀번호는 F-601과 동일하게 저장하지 않으며 접속할 때마다 직접 입력한다 | 사용자명을 등록 시 비워뒀다면 접속 폼에 사용자명 입력란도 함께 표시(F-109와 동일 원칙) — 구현 완료 |
| F-1203 | 접속에 성공하면 쿼리 에디터와 결과 테이블로 구성된 작업 화면으로 전환된다 | 쿼리 실행은 "실행" 버튼 또는 `⌘/Ctrl+Enter`, 결과는 컬럼/행/소요시간과 함께 테이블로 표시 — 구현 완료 |
| F-1204 | 인증 실패 시 접속 폼에 인라인 에러 메시지가 표시되고, 별도 재연결 절차 없이 그 자리에서 비밀번호를 다시 입력해 재시도할 수 있다 | MySQL/PostgreSQL/MS SQL Server 각각의 인증 실패 코드를 `kind:'auth'`로 분류 — 구현 완료·검증됨(3개 엔진 모두) |
| F-1205 | 같은 서버를 여러 번 클릭하면 SSH와 동일하게(01_SSH F-216) 매번 독립된 새 탭·새 연결이 열린다 | 하나의 서버에 여러 쿼리 세션을 동시에 유지 가능 — 구현 완료 |
| F-1206 | 앱 종료 시 활성 SQL 연결도 SSH와 동일하게(F-502) 예외 없이 강제 종료된다 | `db-manager.js`의 `disconnectAll()`을 `before-quit`에서 호출 — 구현 완료 |
| F-1207 | 실행 버튼과 ⌘/Ctrl+Enter는 선택한 SQL을 우선 실행하며, 선택이 없으면 전체 내용을 실행한다 | 같은 세션에서 실행 중인 쿼리의 중복 실행 차단 |
| F-1208 | 결과의 컬럼 순서와 중복 컬럼명을 유지한다 | 세 엔진 모두 배열 행 모드로 값 손실 방지 |
| F-1209 | PostgreSQL/MS SQL Server의 여러 결과를 선택 메뉴로 전환한다 | MySQL은 단일 SQL문; 실행 시간은 전체 요청 소요시간 |
| F-1210 | 접속 중 탭 종료·앱 종료 시 늦게 생성된 연결도 정리하며, 이전 연결 이벤트는 새 세션에 영향을 주지 않는다 | 접속 중복 차단 및 세션 객체 식별 |
| F-1211 | IPC 오류 후 실행 버튼을 복구하고 재연결 이전의 늦은 쿼리 응답을 무시한다 | 비밀번호 입력란은 접속 요청 시 즉시 비움 |

## 4. 데이터 모델 추가 (SQL 전용 필드)

```yaml
# Server(00_공통 정의)에 protocol === "sql"일 때만 사용하는 필드
  sqlEngine: "mysql" | "postgres" | "mssql"
  database: string | null   # 비워두면 서버 기본값 사용
  # authMethod는 항상 "password" 고정(SSH Key 인증 미지원), port 기본값은 엔진별로 다름
  #   mysql 3306 / postgres 5432 / mssql 1433
```

## 6. 범위 밖 (디비버의 더 넓은 기능)

- 스키마/테이블/컬럼 트리 탐색기
- ER 다이어그램
- 결과 테이블에서 셀 직접 편집 → UPDATE 반영
- 쿼리 히스토리, 저장된 쿼리(스니펫)
- 데이터 export/import(CSV, SQL dump 등)
- SSH Key / Windows 인증(AD) / 클라이언트 인증서 등 비밀번호 외 인증 방식


## 7. SQL·FTP 브랜치 개발 기록 (2026-10-06)

- 브랜치: `minaridat/sql-ftp`. 이번 작업은 SQL 매니저·SQL 렌더러·SQL 문서에 한정한다.
- 선택 영역 실행, 실행 중 표시/중복 실행 차단, 여러 결과 선택, 중복 컬럼 보존을 구현했다.
- 접속 대기 중 종료·동일 세션 접속 중복·이전 연결의 지연 이벤트·늦은 쿼리 응답을 처리한다.
- `node --test tests/sql-client.test.cjs`: 연결 수명주기와 결과 처리 회귀 테스트 통과.
- 임시 Docker DB(PostgreSQL 16, MySQL 8, MS SQL Server 2022)에서 실제 드라이버로 중복 컬럼, 오류 후 재실행, 인증 실패를 검증했다. PostgreSQL/MS SQL Server의 여러 SELECT 결과도 검증했다. 테스트 컨테이너는 검증 후 제거했다.
- 임시 jsdom 화면 테스트에서 선택 실행, 중복 실행 차단, 결과 전환, HTML 이스케이프, 늦은 응답 무시, IPC 거부 후 버튼 복구, 비밀번호 입력란 비우기를 검증했다.
- 이번 변경의 Electron 설치본 및 Windows/macOS 전체 UI 검증은 아직 수행하지 않았다.
