# 탭 내 터미널 분할 기능 명세 — 세션 복제/세션 선택 기반 (tmux 비의존)

> 상태: 🚧 구현 중
>
> ⚠️ **설계 변경(tmux 비의존)**: 최초 설계는 "서버에 이미 떠 있는 tmux 세션을 pane 단위로 그대로
> 보여주는" 방식이었다. 하지만 01_SSH에서 이미 tmux 자동 attach를 제거한 것과 같은 이유로
> (서버 측 도구 의존성, tmux 미설치 서버에서 동작 불가) 이 기능도 **클라이언트 쪽에서만 동작하는
> 방식**으로 다시 설계했다 — 분할은 곧 "같은 서버로 새 독립 세션을 하나 더 연다"(F-216과 동일 원칙)이고,
> 추가로 **이미 열려 있는 다른 세션을 그 자리에 가져다 꽂을 수도 있다**(세션 선택기). 서버 측에
> tmux가 있는지 없는지는 이 기능의 동작에 전혀 영향을 주지 않는다.

## 2. 와이어프레임

```
┌───────────────────────────────────────────────────┐
│ [prod-web-01] [prod-db-01] [+]                     │
├───────────────────────┬───────────────────────────┤
│ prod-web-01       [▾ⓧ] │ prod-web-01 #3      [▾ⓧ]  │
│ root@prod-web-01:~#    │ root@prod-web-01:~#        │
│ tail -f /var/log/nginx │ htop                        │
│ ...                     │ ...                         │
│                         ├───────────────────────────┤
│                         │ prod-db-01          [▾ⓧ]  │
│                         │ root@prod-db-01:~#         │
│                         │ df -h                       │
├───────────────────────┴───────────────────────────┤
│ ⌘D 세로분할 · ⌘⇧D 가로분할 · ⌘[/] pane 이동           │
└───────────────────────────────────────────────────┘
```

- 탭 하나는 1개 이상의 pane으로 구성된 레이아웃이다. pane이 1개일 때는 지금까지와 완전히 동일(분할 전 모습, 화면에 분할 UI가 전혀 안 보임)
- 각 pane 헤더에는 그 pane이 지금 보여주는 세션 이름(`서버명` 또는 `서버명 #N`), **세션 선택기(`[▾]`)**, **pane 닫기(`ⓧ`)**가 있다
- "세로분할"/"가로분할"을 누르면 새 pane이 생기고, 그 안에 **같은 서버로 새 독립 세션이 자동으로 열린다**(F-216과 동일한 흐름 — 비밀번호를 다시 입력해야 할 수 있음)
- pane 헤더의 세션 선택기를 열면 "새 세션" 외에 **현재 앱에서 열려 있는 다른 모든 세션**(다른 탭의 세션 포함)이 목록으로 뜬다. 하나를 고르면 그 세션이 이 pane으로 옮겨오고, 원래 있던 자리(다른 탭 전체 또는 다른 pane)는 비워진다
- pane 크기는 경계선 드래그로 조절, 포커스된 pane은 테두리로 강조
- v1 범위: 한 탭 안의 모든 pane은 **하나의 방향(가로 일렬 또는 세로 일렬)만** 가진다 — iTerm2/tmux처럼 가로·세로가 섞인 자유 트리 분할은 범위 밖(6절 참고)
- 01_SSH의 동시 입력 모드(F-208~212, S8)는 "탭" 단위였다면, 여기서는 "pane" 단위로도 동일한 동시 입력을 적용할 수 있다

## 3. 기능 명세 (F-801 ~ F-808)

| ID | 요구사항 | 비고 |
|---|---|---|
| F-801 | 하나의 탭 내에서 세션을 가로/세로로 pane 분할해 배치할 수 있다 | v1은 한 탭 안에서 가로 일렬 또는 세로 일렬 중 하나의 방향만 지원(6절 범위 밖 참고) |
| F-802 | 분할로 새로 생긴 pane에는 기본적으로 **같은 서버의 새 독립 세션**이 열린다 | 01_SSH F-216과 동일한 "클릭=새 세션" 원칙 재사용. 서버 측 tmux 등 외부 도구에 전혀 의존하지 않는다 |
| F-803 | 각 pane 헤더의 세션 선택기로, 새 세션 대신 **현재 앱에서 열려 있는 다른 세션**(다른 탭 포함)을 그대로 가져와 이 pane에 배치할 수 있다 | 세션은 한 번에 한 자리(탭 전체 또는 어떤 탭의 pane 하나)에만 존재한다 — 가져오면 원래 자리는 비워진다(F-803a) |
| F-803a | 세션을 가져온 뒤 원래 있던 자리가 "탭 전체"였다면 그 탭은 자동으로 닫힌다. 원래 있던 자리가 "다른 탭의 pane"이었다면 그 pane은 제거되고, pane이 1개만 남으면 분할 UI가 사라져 일반 탭으로 되돌아간다 | 빈 자리를 남기지 않는다 — "세션 없음" 상태의 pane은 존재하지 않음 |
| F-804 | 단축키로 pane 간 포커스를 이동할 수 있다 | `⌘[` / `⌘]` 또는 방향키 조합 |
| F-805 | pane 경계를 드래그해 크기를 조절할 수 있다 | |
| F-806 | 분할 레이아웃(pane 개수·방향)을 로컬에 저장하고 재접속 시 복원한다 | 레이아웃(모양)만 복원되고, 각 pane의 세션 자체는 재접속 시 새로 연결된다(세션은 비영속 — 00_공통 Session 데이터모델 참고). 🔲 v1 범위 밖, 나중에 추가 |
| F-807 | 01_SSH의 동시 입력 모드(F-208)는 pane 단위 선택에도 동일하게 적용된다 | |
| F-808 | pane을 닫으면 그 pane의 세션만 종료된다(같은 탭의 다른 pane·다른 탭에는 영향 없음). 앱 종료 시에는 F-502에 따라 모든 pane의 세션이 예외 없이 강제 종료된다 | 00_공통 F-502 원칙 승계 |

## 4. 데이터 모델 추가

```yaml
# 탭(Session, 00_공통 정의) 하나가 여러 pane으로 구성될 수 있도록 확장
TabLayout (런타임, 비영속 — v1. F-806 구현 시 로컬 저장소로 영속화):
  tabId: string              # 탭바에 보이는 탭의 id
  orientation: "row" | "column" | null   # pane이 1개면 null
  paneIds: string[]          # 각 원소는 독립된 Session(tabId)을 가리킴 — 첫 pane은 보통 tabId 자신과 동일
```

## 5. 완료 기준

- [ ] 탭 안에서 세션을 가로/세로로 분할할 수 있고, 새 pane에는 기본적으로 새 독립 세션이 연결된다
- [ ] pane 헤더의 세션 선택기로 다른 곳에 열려 있는 세션을 이 pane으로 가져올 수 있고, 원래 자리는 자동으로 정리된다
- [ ] pane 크기 드래그 조절, pane 간 단축키 포커스 이동이 동작한다
- [ ] pane을 닫으면 그 pane의 세션만 종료되고, 1개만 남으면 분할 UI가 사라진다
- [ ] 앱 종료 시 모든 pane의 세션이 예외 없이 강제 종료된다(F-502)
