## 2. 와이어프레임

### S3. SSH 터미널 탭

```
┌───────────────────────────────────────────────────┐
│ [prod-web-01 ●연결됨]  [prod-web-01 #2 ●연결됨] [+] │
├───────────────────────────────────────────────────┤
│ root@prod-web-01:~# ls -al                           │
│ ...                                                  │
│                                                       │
│                                                       │
│                                                       │
├───────────────────────────────────────────────────┤
│ 🟢 연결됨 · SSH · 10.0.1.23:22                       │
└───────────────────────────────────────────────────┘
```

- 같은 서버를 다시 클릭하면 기존 탭으로 포커스만 이동하지 않고 항상 새 탭·새 세션이 열린다(F-216) — 두 번째 탭부터는 "서버명 #2"처럼 구분 표시
- 탭 닫기(×) 시: 그 탭의 SSH 연결만 종료(같은 서버의 다른 탭에는 영향 없음)
- 연결 끊김(네트워크 등) 시 탭 타이틀에 🔴 표시 + 하단 상태바에 "재연결 시도 중..." + 자동 재접속(exponential backoff) — 🔲 미구현, 현재는 수동 재연결 버튼(F-215)만 있음

### S8. 다중 서버 동시 명령 실행 (Broadcast 모드)

```
┌────────────────────────────────────────────────────────────────┐
│ ⚠ 동시 입력 모드 · 3개 서버 선택됨                     [모드 끄기] │
├────────────────────┬────────────────────┬───────────────────────┤
│ prod-web-01         │ prod-web-02         │ prod-web-03           │
│ root@prod-web-01:~# │ root@prod-web-02:~# │ root@prod-web-03:~#   │
│ systemctl restart   │ systemctl restart   │ systemctl restart     │
│ nginx                │ nginx                │ nginx                  │
│ root@prod-web-01:~# │ root@prod-web-02:~# │ root@prod-web-03:~#   │
├────────────────────┴────────────────────┴───────────────────────┤
│ >_ 여기에 입력하면 선택된 3개 서버에 동시 전송됩니다                 │
└────────────────────────────────────────────────────────────────┘
```

- 탭바에서 SSH 탭 2개 이상을 체크박스로 다중 선택 → `[동시 입력 모드]` 버튼으로 진입
- 하나의 입력창에 입력하면 선택된 모든 탭에 동일 keystroke가 그대로 전송된다
- 모드 중에는 상단에 빨간 경고 배너를 항상 노출해 "지금 여러 서버에 동시 입력 중"임을 인지시킴 — 운영(prod) 그룹 서버가 포함된 경우 진입 시 1회 확인 다이얼로그는 🔲 미구현
- `[모드 끄기]` 시 각 탭은 독립 입력으로 즉시 복귀 — 개별 SSH 연결에는 영향 없음

## 3. 기능 명세 (F-201 ~ F-216)

| ID | 요구사항 | 비고 |
|---|---|---|
| F-201 | 서버 클릭 시 새 탭에서 SSH 접속이 시작된다 | 클릭할 때마다 항상 새 탭·새 세션을 연다(F-216) — 구현 완료(`ssh2` + `xterm.js`) |
| F-202 | 터미널은 xterm 호환(색상, 커서, 리사이즈 등)을 지원한다 | xterm.js 기준 — 구현 완료 |
| F-203 | 탭 간 전환 및 다중 세션 동시 유지가 가능하다 | 구현 완료 |
| F-204 | 연결 끊김 시 자동 재연결을 시도한다 | backoff: 1s→2s→5s→10s, 최대 5회 — 🔲 미구현(현재는 "재연결" 버튼으로 수동 재시도만 가능) |
| F-205 | ~~접속 시 지정된 이름으로 tmux 세션을 자동 attach한다~~ | **제거됨.** 같은 이름의 tmux 세션에 여러 탭이 동시에 attach되어 한 서버로 독립된 세션을 여러 개 열 수 없었고, tmux가 설치되지 않은 서버에서는 접속 직후 명령 자체가 실패했다. tmux 등 세션 유지 도구는 자동 실행하지 않으며, 필요하면 사용자가 터미널 안에서 직접 실행한다 |
| F-206 | ~~탭을 닫아도 서버 측 tmux 세션은 유지되어 재접속 시 이어진다~~ | F-205 제거에 따라 더 이상 해당 없음 — 탭을 닫으면 그 탭의 클라이언트↔서버 연결만 종료된다 |
| F-207 | 터미널 폰트/크기/테마(다크·라이트)를 설정할 수 있다 | 🔲 미구현(현재 폰트/테마 고정) |
| F-208 | 열려 있는 SSH 탭 중 2개 이상을 다중 선택해 "동시 입력 모드"를 켤 수 있다 | S8, Termius Multi Exec 대응 — 구현 완료(v1: 토글을 켜면 열려 있는 모든 SSH 탭이 자동으로 그룹이 됨, 탭별 체크박스 선택은 추후 고도화) |
| F-209 | 동시 입력 모드에서는 하나의 입력이 선택된 모든 탭에 동일하게 전송되며, 선택된 탭은 타일 형태로 함께 표시된다 | 입력 전송 + **탭별 체크박스 선택 구현 완료** — 모드를 켜면 실제 세션이 있는 SSH 탭마다 체크박스가 나타나고 기본은 전체 선택, 개별적으로 해제해 그룹에서 뺄 수 있다. **타일 동시 표시(여러 터미널을 한 화면에 나란히)는 아직 범위 밖** — 탭 UI(한 번에 한 pane만 보임)는 유지한 채 입력만 백그라운드로 브로드캐스트됨. 이 메커니즘은 셸 접속 이후뿐 아니라 **비밀번호/Key Passphrase 입력 단계에서도 동일하게 동작** |
| F-210 | 동시 입력 모드 중에는 화면에 경고 배너("N개 서버에 동시 입력 중")가 항상 표시되어 오탐(잘못된 서버에 명령 전송)을 방지한다 | 배너 구현 완료. 운영 그룹 포함 시 진입 확인 다이얼로그는 🔲 미구현 |
| F-211 | 동시 입력 모드는 언제든 즉시 끌 수 있으며, 꺼도 각 탭의 개별 SSH 연결은 그대로 유지된다 | 구현 완료 |
| F-212 | 동시 입력 모드 여부와 무관하게, 앱 종료 시 강제 연결 종료 정책(F-502)은 선택된 모든 탭에 동일하게 적용된다 | PC 클라이언트↔서버 간 통신 세션은 예외 없이 끊는다 — 구현 완료·검증됨 |
| F-213 | 탭 전환은 키보드 단축키로 가능하다: `⌘/Ctrl + 1~9`(해당 순번 탭으로 바로 이동), `⌘+⌥+←/→`(Mac) 또는 `Ctrl+Tab / Ctrl+Shift+Tab`(Windows·Linux)으로 이전·다음 탭 이동, `⌘+</⌘+>`(Mac) 또는 `Ctrl+</Ctrl+>`(Windows)로도 동일하게 이전·다음 탭 이동 | 모든 단축키는 현재 프로토콜 필터(F-501)로 화면에 보이는 탭 기준으로 번호가 매겨지고 동작한다 |
| F-214 | 인증 실패(비밀번호 거절, Key Passphrase 오류) 시 실제 `ssh` 명령어처럼 "Permission denied, please try again."을 띄우고 그 자리에서 즉시 재입력받는다 — 재연결 버튼을 누를 필요 없음 | 최대 3회까지 자동 재시도, 3회 모두 실패하면 "Permission denied (password/publickey)."로 최종 실패 처리 후 재연결 버튼 필요. 연결 거부·타임아웃 등 **재입력해도 의미 없는 오류는 재시도하지 않고 바로 최종 에러**로 표시 — 구현 완료 |
| F-215 | 열려 있는 SSH 탭에서 세션이 끊겼거나(disconnected) 최종 인증 실패(error) 상태일 때, 탭의 서버명 옆에 재연결 아이콘 버튼이 나타나 클릭 한 번으로 즉시 재접속(F-109/F-214 흐름 재진입)할 수 있다 | 연결 중(connecting)·인증 프롬프트 중(prompting)·정상 연결(connected) 상태에서는 숨김. 클릭 시 해당 탭이 자동으로 활성화됨 — 구현 완료 |
| F-216 | 사이드바에서 같은 서버를 여러 번 클릭하면 매번 독립된 새 탭·새 SSH 세션이 열린다(기존 탭으로 포커스만 이동하지 않음) | 같은 서버에 서로 다른 작업을 병행하거나, 각기 다른 사용자명(F-109)으로 동시에 접속하는 경우 대응. 탭 이름은 "서버명", "서버명 #2"처럼 구분 표시. 사이드바 상태 점은 그 서버로 열린 세션 중 하나라도 연결돼 있으면 켜짐으로 표시 — 구현 완료 |

## 4. 데이터 모델 추가 (SSH 전용 필드)

```yaml
# Server(00_공통 정의)에 protocol === "ssh"일 때만 사용하는 필드
  authMethod: "password" | "publickey"   # 비밀번호/Passphrase 값 자체는 저장하지 않음(F-601)
  keyFilePath: string | null              # SSH Key "경로"만 저장 — 파일 자체는 비밀이 아님
```

## 5. 완료 기준

- [x] 등록된 서버를 클릭하면 5초 이내 SSH 접속 및 터미널 표시가 이루어진다 (비밀번호는 터미널 안에 직접 뜨는 프롬프트로 입력) — 실제 SSH 서버 대상 e2e 검증 완료
- [x] 비밀번호 인증이 정상 동작한다(실제 접속·명령 실행·연결 종료까지 e2e 검증 완료) / Key 인증은 키 파일 로드→인증 시도 배관까지 검증, **실제 키를 accept하는 서버 대상 성공 케이스는 아직 미검증**
- [x] 같은 서버를 여러 번 클릭하면 매번 독립된 새 탭·새 세션이 열린다(F-216)
- [x] 인증 실패 시 ssh 명령어처럼 그 자리에서 재입력받고, 최대 3회까지 자동 재시도한다(F-214)
- [x] SSH 탭 2개 이상을 선택해 동시 입력 모드를 켜고 끌 수 있으며, 모드 중에는 경고 배너가 항상 보인다 — 비밀번호 프롬프트 단계까지 포함해 멀티 서버 동시 입력 e2e 검증 완료
- [x] 탭 전환이 `⌘/Ctrl+1~9`, `⌘⌥←/→`(또는 `Ctrl+Tab`), `⌘</⌘>`(또는 `Ctrl+</>`) 단축키로 모두 동작한다
- [x] 프로그램 종료(정상/강제 포함) 시 모든 활성 SSH 연결이 예외 없이 종료된다 — 실제 SSH 서버로 앱 종료→서버측 연결 종료까지 확인
