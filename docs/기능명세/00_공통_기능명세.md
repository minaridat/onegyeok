# 공통 기능 명세 — 서버 등록/관리, 연결 유지·종료, 보안 아키텍처

> 상위 문서: [../기획서.md](../기획서.md)
> 이 문서는 **연결 종류(SSH/SQL/RDP/...)와 무관하게 모든 연결에 공통으로 적용되는** 화면·기능·보안 원칙을 다룬다.
> 각 연결 종류별 세부 사항은 [README.md](./README.md)의 파일 목록을 참고.
>
> ⚠️ **정책 변경(자동로그인 폐기)**: 사내 보안 담당자 확인 결과 ISMS 인증 심사에서는 심사위원 앞에서 비밀번호를 직접 입력하는
> 절차가 요구되어, 비밀번호 자동 저장/자동 로그인 기능은 전면 폐기한다. 이 원칙은 모든 연결 종류에 예외 없이 적용된다.

## 2. 와이어프레임

### S1. 메인 화면

```
┌───────────────────────────────────────────────────────────────────┐
│ onegyeok                                              [+ 서버 등록] │
├───────────────┬───────────────────────────────────────────────────┤
│ 🔍 서버 검색   │  [prod-web-01 ×] [prod-db-01 ×] [+]                │
│               ├───────────────────────────────────────────────────┤
│ ▾ 운영         │                                                   │
│   ● prod-web-01│  $ ssh prod-web-01 접속됨                          │
│   ● prod-db-01 │  Last login: Tue Sep 30 ...                       │
│   ○ prod-cache │  root@prod-web-01:~#                               │
│ ▾ 스테이징     │                                                   │
│   ○ stg-web-01 │                                                   │
│ ▾ 개발         │                                                   │
│   ○ dev-01     │                                                   │
│               │                                                   │
│ [+ 그룹 추가]  │                                                   │
└───────────────┴───────────────────────────────────────────────────┘
  ● = 연결됨(활성 세션)   ○ = 미연결
```

- 서버 클릭 → 매번 독립된 새 탭·새 세션을 연다(연결 종류별 세부 사항은 각 파일의 "다중 세션" 항목 참고)
- 그룹(운영/스테이징/개발 등)은 드래그로 재배치, 우클릭으로 이름 변경/삭제. 같은 그룹 내 서버 순서도 드래그로 재정렬 가능(F-110)
- 서버 우클릭 메뉴: `연결 / 수정 / 복제 / SFTP로 열기(03_SFTP) / 삭제`
- 상단바에는 `[서버 관리]` 버튼이 있어 S7(전체 목록/편집 테이블)을 열 수 있다
- 왼쪽에는 프로토콜 컨텍스트 전환 레일(전체/SSH/SQL/RDP/VNC/SFTP/Web)이 있어, 필터 전환·탭 이동 중에는 기존 연결이 끊기지 않는다(F-501)

### S2. 서버 등록/수정 모달

```
┌─────────────────────────────────────────┐
│ 서버 등록                          [×]   │
├─────────────────────────────────────────┤
│ 이름       [ prod-web-01            ]    │
│ 그룹       [ 운영            ▾]          │
│ 프로토콜   [ SSH ▾]                      │
│───────────────────────────────────────── │
│ 호스트     [ 10.0.1.23              ]    │
│ 포트       [ 22   ]                      │
│ 사용자명(선택) [ 비워두면 접속시 입력 ]   │
│                                           │
│ (아래는 프로토콜에 따라 다른 필드가 노출됨) │
│ 인증 방식  ( ) 비밀번호   (•) SSH Key     │
│   Key 파일 [ ~/.ssh/id_rsa    ] [찾아보기] │
│ 점프 호스트(선택) [ bastion-01      ▾]    │
│───────────────────────────────────────── │
│ 비밀번호·Passphrase는 저장하지 않습니다 —  │
│ 접속할 때마다 직접 입력합니다              │
│                                           │
│              [ 연결 테스트 ]  [저장] [취소]│
└─────────────────────────────────────────┘
```

- 프로토콜 하나당 새 등록 화면을 만들지 않는다 — 이 모달 하나를 공유하고, 프로토콜 선택에 따라 필드만 동적으로 보이거나 숨는다(예: SQL은 점프호스트 대신 DB 엔진·데이터베이스명을 보여줌 — 02_SQL 참고)
- `연결 테스트` 클릭 시 그 자리에서 비밀번호(또는 Passphrase)를 1회 입력받아 실제 핸드셰이크만 수행(연결 후 즉시 종료), 성공/실패 인라인 표시 — 입력값은 테스트 직후 폐기, 저장하지 않음
- 비밀번호/Passphrase 입력란과 "자동저장" 옵션은 없음 — 등록 단계에서는 인증 *방식*만 선택하고, 실제 값은 매 접속 시점에 입력

### S7. 서버 관리 (전체 목록/편집)

```
┌───────────────────────────────────────────────────────────────────────────┐
│ 서버 관리                                              [+ 서버 추가]   [×]  │
├───────────────────────────────────────────────────────────────────────────┤
│ 🔍 검색...                            프로토콜 [전체 ▾]   그룹 [전체 ▾]     │
├────────────┬─────────┬───────┬────────────┬──────┬────────────┬──────────┤
│ 이름        │ 그룹     │ 프로토콜│ 호스트       │ 포트  │ 인증 방식    │ 마지막 접속│
├────────────┼─────────┼───────┼────────────┼──────┼────────────┼──────────┤
│ prod-web-01 │ 운영     │ SSH   │ 10.0.1.23   │ 22   │ SSH Key     │ 12분 전  │ [✎][🗑]
│ prod-db-01  │ 운영     │ SSH   │ 10.0.1.31   │ 22   │ 비밀번호     │ 1시간 전  │ [✎][🗑]
│ win-app-01  │ 운영     │ RDP   │ 10.0.1.55   │ 3389 │ Windows 계정 │ 6분 전   │ [✎][🗑]
│ stg-web-01  │ 스테이징  │ SSH   │ 10.0.2.10   │ 22   │ 비밀번호     │ -        │ [✎][🗑]
│ dev-01      │ 개발     │ SSH   │ 192.168.0.15│ 22   │ 비밀번호     │ -        │ [✎][🗑]
├────────────┴─────────┴───────┴────────────┴──────┴────────────┴──────────┤
│ 선택된 항목: 0개        [선택 삭제]  [선택 그룹 이동 ▾]                      │
└───────────────────────────────────────────────────────────────────────────┘
```

- 컬럼 헤더 클릭으로 정렬, 검색창은 이름/호스트/그룹 대상 즉시 필터링
- 행 더블클릭 또는 `[✎]` 클릭 → S2(서버 등록/수정 모달)가 해당 서버 값으로 프리필되어 열림
- 체크박스로 다중 선택 후 일괄 삭제/그룹 이동
- 트리 뷰(S1 사이드바)와 데이터 원본은 동일 — 여기서 수정하면 트리에도 즉시 반영

## 3. 기능 명세 (Functional Requirements)

### 3.1 서버 등록/관리 (F-101 ~ F-110)

| ID | 요구사항 | 비고 |
|---|---|---|
| F-101 | 사용자는 서버를 이름/그룹/호스트/포트/인증정보로 등록할 수 있다 | 프로토콜 선택에 따라 추가 필드가 달라짐(각 연결 종류 파일 참고) |
| F-102 | 서버는 그룹(폴더) 단위로 분류, 트리 UI로 표시된다 | 드래그로 그룹 이동 |
| F-103 | 서버 목록은 이름/호스트 기준 검색·필터링 가능하다 | |
| F-104 | 등록 시 "연결 테스트"로 실제 접속 가능 여부를 즉시 확인할 수 있다 | 타임아웃 5초 |
| F-105 | 인증 방식으로 비밀번호 또는 SSH Key(+passphrase)를 선택할 수 있다 | SSH에만 해당(SQL 등 다른 연결 종류는 비밀번호 인증만 지원) |
| F-106 | 점프 호스트(Bastion)를 경유한 접속을 등록할 수 있다 | 기 등록된 SSH 서버 중 선택 |
| F-107 | 서버 정보 복제/수정/삭제가 가능하다 | 삭제 시 확인 다이얼로그 |
| F-108 | "연결 정보" 패널에서 서버별 자유 텍스트 메모를 남길 수 있다 | 임시 복붙용 스크래치패드. 화면에 "민감정보 금지" 경고 상시 노출. 입력 후 자동 저장(디바운스) + 포커스 아웃 시 즉시 저장, 저장 결과를 "저장됨" 상태 표시로 알림 — 구현 완료(`src/main/main.js`의 `memo:*` IPC) |
| F-109 | 사용자명은 등록 시 선택 입력이다 — 비워두면 접속할 때마다 직접 입력받는다 | 같은 서버에 여러 사용자로 번갈아 접속하는 경우(예: 개인 계정/서비스 계정) 대응. 입력값은 저장하지 않으며 접속 1회에만 사용(F-601). 구현 방식은 연결 종류마다 다름 — SSH는 터미널에 `login as:` 프롬프트, SQL은 접속 폼의 사용자명 입력란 |
| F-110 | 같은 그룹 내 서버는 드래그 앤 드롭으로 순서를 재정렬할 수 있다 | 그룹 간 이동은 지원하지 않음(동일 그룹 내에서만 순서 변경) — 구현 완료 |

### 3.2 서버 관리 (전체 목록/편집) (F-401 ~ F-403)

| ID | 요구사항 | 비고 |
|---|---|---|
| F-401 | 등록된 모든 서버를 테이블(그리드) 형태로 한 화면에서 조회할 수 있다 | 컬럼: 이름/그룹/프로토콜/호스트/포트/인증 방식/마지막 접속일, S7 |
| F-402 | 테이블에서 검색, 컬럼 정렬, 프로토콜·그룹 필터링이 가능하다 | |
| F-403 | 테이블 행 편집 시 S2 모달이 해당 서버 값으로 프리필되어 열리며, 모든 등록 필드를 수정할 수 있다. 다중 선택 후 일괄 삭제·그룹 이동도 지원한다 | 트리 뷰(S1)와 데이터 원본 공유 |

### 3.3 연결 유지 및 세션 종료 정책 (F-501 ~ F-502)

| ID | 요구사항 | 비고 |
|---|---|---|
| F-501 | 왼쪽 프로토콜 레일의 컨텍스트 전환이나 탭 이동은 기존 연결(SSH/SQL/RDP/VNC/SFTP/Web)을 끊지 않는다 | 필터는 표시 여부만 바꾸는 UI 동작, 연결 자체와 무관 |
| F-502 | 프로그램이 종료되는 시점(정상 종료·강제 종료 포함)에는 예외 없이 모든 활성 연결을 강제로 종료하고, 메모리 상에 복호화되어 있던 자격증명도 즉시 폐기한다 | 보안 요구사항(ISMS-P) — SSH/SQL 구현 완료·검증됨, 나머지 연결 종류는 구현 시 동일 정책 적용 필수 |

### 3.4 보안 아키텍처 (ISMS-P 대응) (F-601 ~ F-609)

| ID | 요구사항 | 비고 |
|---|---|---|
| F-601 | 비밀번호·SSH Key passphrase 등 로그인 인증정보는 앱의 어떤 저장소(설정 파일, DB, OS Keychain 포함)에도 저장하지 않으며, 접속할 때마다 사용자가 직접 입력한다 | **자동로그인 폐기 — 핵심 요구사항**(심사위원 확인 요구사항 대응). SSH는 터미널 안에 `user@host's password:` 프롬프트를 직접 띄우는 방식, SQL은 접속 폼으로 구현 — 구현 완료 |
| F-602 | 로그인 인증정보 대신, 호스트/IP/그룹 등 서버 목록(인프라 토폴로지) 데이터를 AES-256-GCM 등 검증된 알고리즘으로 암호화하여 로컬에 저장한다 | 암호화 키는 마스터 패스워드로부터 PBKDF2/Argon2id 등 KDF로 파생, OS Keychain은 이 키 보호 용도로만 사용 — 🔲 미구현 |
| F-603 | 앱 자체는 마스터 패스워드로 보호되며, 설정 가능한 유휴 시간(기본 10분) 초과 시 자동 잠금된다 | 서버 목록 열람 통제(단말기 자리비움 보호) — 로그인 비밀번호 볼트 아님 — 🔲 미구현 |
| F-604 | 모든 서버 접속 시도는 성공/실패 여부와 관계없이 로컬 접속 로그에 기록된다 | 기록 항목: 일시, 대상 서버, 프로토콜, 결과, 실패 사유 — 🔲 미구현 |
| F-605 | 접속 로그는 앱 UI를 통한 수정·삭제가 불가능한 읽기 전용 형태로 보관되며, 보관 기간을 설정할 수 있다 | 심사 시 접속 이력 제출 대응 — 🔲 미구현 |
| F-606 | VNC 등 프로토콜 자체의 전송 구간 암호화가 없거나 약한 경우, SSH 터널링 등 보호 수단 사용을 기본값으로 안내·적용한다 | 06_VNC 설계에 반영 |
| F-607 | 연결 유지 및 강제 종료 정책은 3.3절(F-501, F-502)을 따른다 | |
| F-608 | (참고) 조직의 심사 범위에 따라 국정원 검증필 암호모듈(KCMVP) 연동이 요구될 수 있어, 암호화 레이어는 모듈 교체가 가능하도록 추상화한다 | 필수 요구사항 확정 전까지는 설계상 여지만 확보 |
| F-609 | 자동로그인/비밀번호 자동 저장·자동 재입력 기능은 시스템 어디에도 존재하지 않는다 | 심사 대응을 위한 명시적 금지 요구사항 (QA 체크 항목) — 모든 연결 종류에 예외 없이 적용 |

## 4. 데이터 모델 — 공통 필드

```yaml
Server:
  id: uuid
  name: string
  groupId: uuid | null
  protocol: "ssh" | "sql" | "rdp" | "vnc" | "sftp" | "web"   # 연결 종류별 추가 필드는 각 파일 참고
  host: string
  port: number
  username: string | null  # 선택(F-109) — null이면 접속할 때마다 직접 입력받음
  jumpHostId: uuid | null   # SSH 계열에서만 사용
  memo: string | null      # 자유 텍스트 메모(F-108). 현재는 Electron safeStorage로 암호화해
                           # 별도 파일(memos.json, 서버 id 키)에 저장 — 서버 목록 전체 영속화(F-602) 구현 시 통합 예정
  createdAt: datetime
  updatedAt: datetime

Group:
  id: uuid
  name: string
  parentId: uuid | null
  order: number

Session (런타임, 비영속):
  serverId: uuid
  connectionState: "connecting" | "connected" | "reconnecting" | "disconnected"
  tabId: string   # 서버 하나에 여러 탭(세션)을 동시에 열 수 있으므로 tabId ≠ serverId
  lastError: string | null

ConnectionLog (읽기 전용, 수정·삭제 API 없음):
  id: uuid
  serverId: uuid
  protocol: string
  result: "success" | "failure"
  reason: string | null       # 실패 사유 (예: 인증 실패, 타임아웃 등)
  clientUser: string          # OS 로그인 사용자 (감사용)
  startedAt: datetime
  endedAt: datetime | null

Settings:
  autoLockMinutes: number      # 기본 10, F-603
  logRetentionDays: number     # 접속 로그 보관 기간, F-605
```

연결 종류별 추가 필드(예: SSH의 `authMethod`/`keyFilePath`, SQL의 `sqlEngine`/`database`)는 각 파일의
"데이터 모델 추가" 절에 정의한다.
