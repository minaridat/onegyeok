# RDP 기능 명세 — 원격 데스크톱 클라이언트

> 상위 문서: [../기획서.md](../기획서.md) · 공통 원칙: [00_공통_기능명세.md](./00_공통_기능명세.md)
> 상태: 🚧 구현 중. 기술 스택(Apache Guacamole 기반)은 [../기술스택/03_RDP_기술스택.md](../기술스택/03_RDP_기술스택.md) 참고.
>
> ⚠️ **설계 확정**: 기존 플레이스홀더(정적 `.win` 블록)를 실제 `guacd` 연동 `<canvas>` 렌더링으로 교체한다.
> SSH/SQL과 같은 패턴 — 탭을 열면 먼저 접속 폼(사용자명·비밀번호)을 보여주고, 성공해야 실제 화면으로 전환된다.
> **RDP는 SSH/SQL과 달리 `guacd`라는 외부 데몬이 반드시 떠 있어야 접속할 수 있다**(기술스택 문서 참고) — 이
> 전제가 SSH/SQL에는 없던 새로운 실패 모드(F-905a)를 만든다.

## 1. 화면

새 화면 번호는 필요 없다 — 00_공통의 S1(메인 화면)에서 RDP 서버를 클릭하면 열리는 탭이 곧 RDP 세션 화면이다.

### 와이어프레임

```
┌───────────────────────────────────────────────────┐
│ win-app-01 · RDP · 10.0.1.55:3389     [🗐][⛶][⊗]     │
├───────────────────────────────────────────────────┤
│              사용자명 [ Administrator        ]      │
│              비밀번호 [ ************         ]      │
│                          [ 접속 ]                    │
└───────────────────────────────────────────────────┘
                        ↓ 접속 성공
┌───────────────────────────────────────────────────┐
│ win-app-01 · RDP · 1920×1080          [🗐][⛶][⊗]     │
├───────────────────────────────────────────────────┤
│                                                       │
│              (guacd가 전송하는 실제 원격 화면,         │
│               <canvas>에 렌더링)                      │
│                                                       │
├───────────────────────────────────────────────────┤
│ 🟢 연결됨 · RDP · 10.0.1.55:3389                     │
└───────────────────────────────────────────────────┘
```

- 접속 폼은 SQL 접속 폼(02_SQL S13)과 같은 패턴 — 사용자명을 등록 시 비워뒀다면 폼에 사용자명 입력란도 함께 표시(F-109)
- 접속 성공 시 캔버스로 전환, 마우스/키보드 입력이 캔버스에 포커스된 동안 원격 세션으로 그대로 전달된다
- 툴바: 서버명·해상도 표시, 클립보드 동기화 토글(F-903), 전체화면(F-906), 연결 종료
- 같은 서버를 여러 번 클릭하면 SSH/SQL과 동일하게(F-216/F-1205) 매번 새 탭·새 연결이 열린다

## 2. 기능 명세 (F-901 ~ F-908)

| ID | 요구사항 | 비고 |
|---|---|---|
| F-901 | RDP 프로토콜로 Windows(또는 RDP를 지원하는) 서버에 원격 데스크톱 접속해 화면을 실시간으로 본다 | `guacd` + `guacamole-lite`(메인 프로세스) + `guacamole-common-js`(렌더러, `<canvas>` 렌더링) — 구현 완료. 기술스택 문서 참고 |
| F-902 | 해상도를 자동(창 크기에 맞춤) 또는 수동으로 설정할 수 있다 | v1은 pane 크기에 맞춰 자동 — 구현 완료. 수동 지정은 🔲 범위 밖 |
| F-903 | 클립보드 동기화를 켜고 끌 수 있다 | 🔲 미구현(v1 범위 밖, 6절 참고) |
| F-904 | 로컬 드라이브를 원격 세션에 마운트할 수 있다 (선택 기능) | 🔲 미구현(v1 범위 밖) |
| F-905 | 인증정보는 저장하지 않고 접속마다 직접 입력한다 | 00_공통 F-601 원칙 — SSH/SQL과 동일하게 탭을 열면 사용자명(선택)·비밀번호 입력 폼을 먼저 보여주고, 성공해야 실제 화면으로 전환 — 구현 완료 |
| F-905a | `guacd`에 연결할 수 없을 때는 "원격 데스크톱 서비스에 연결할 수 없습니다(guacd 확인 필요)"처럼 원인을 구분할 수 있는 에러를 보여준다 | RDP 서버 자체의 인증 실패(F-905)와 `guacd` 자체가 꺼져 있는 상황을 구분해서 보여준다 — 구현 완료 |
| F-906 | 전체화면 전환을 지원한다 | 🔲 미구현(v1 범위 밖) |
| F-907 | 연결이 끊기면 자동 재연결을 시도한다 | 01_SSH F-204와 동일 정책 — SSH 쪽도 아직 미구현이므로 함께 미구현. v1은 탭의 "재연결" 버튼으로 수동 재시도(F-215 패턴 재사용) |
| F-908 | 세션 상태(연결됨/연결 끊김/오류)를 화면에 표시한다 | 구현 완료. 지연시간(ms) 표시는 🔲 범위 밖 |

## 3. 데이터 모델 추가 (RDP 전용 필드)

```yaml
# Server(00_공통 정의)에 protocol === "rdp"일 때만 사용하는 필드
  # v1은 추가 등록 필드가 없다 — host/port(기본 3389)/username만으로 충분하고,
  # 비밀번호는 SSH/SQL과 동일하게 접속 시점에 폼으로 입력받아 저장하지 않는다.
  # 아래는 F-902~904 구현 시 추가 예정인 필드(아직 미사용):
  rdpResolution: "auto" | string   # 예: "1920x1080"
  rdpClipboardSync: boolean        # 기본 false
  rdpDriveMount: boolean           # 기본 false
```

## 4. 완료 기준

- [x] RDP 서버를 등록하고 접속 폼에서 사용자명·비밀번호를 입력해 실제 원격 화면이 `<canvas>`에 렌더링된다 — `guacd` + 테스트용 xrdp 서버(Docker) 대상 e2e 검증 완료
- [x] 같은 서버를 여러 번 클릭하면 매번 독립된 새 탭·새 연결이 열린다 — e2e 검증 완료
- [x] 대상 서버에 접속할 수 없을 때(네트워크 오류) 인라인 에러가 표시되고 그 자리에서 다시 시도할 수 있다 — e2e 검증 완료
- [x] 인증 실패(CLIENT_UNAUTHORIZED/CLIENT_FORBIDDEN) → `kind:'auth'` 분류 로직은 실제 `Guacamole.Status.Code` 상수로 단위 검증 완료. **실제 서버가 틀린 비밀번호를 거절하는 전체 흐름은 e2e 미검증** — 테스트용 xrdp 컨테이너의 PAM 설정이 느슨해 비밀번호를 가리지 않고 받아줘서(테스트 픽스처의 한계), 실제 계정 보안이 걸린 서버로 재검증 필요
- [ ] `guacd` 프로세스 자체가 꺼져 있을 때의 에러 구분(F-905a) — 로컬 WS 서버 자체를 못 띄우는 경우(`kind:'guacd'`)는 코드상 처리돼 있으나 e2e 미검증. guacd는 떠 있지만 대상 호스트가 없는 경우는 검증 완료(네트워크 오류로 분류됨)
- [x] 마우스 클릭/이동, 키보드 입력이 원격 세션으로 전달되도록 배선돼 있다(`Guacamole.Mouse`/`Guacamole.Keyboard`) — 실제 입력이 원격 데스크톱에 도달하는지(화면에 반영되는지)는 수동 확인 필요, 자동화 테스트로는 캔버스가 그려지는 것까지만 검증
- [x] 앱 종료 시 활성 RDP 연결도 예외 없이 강제 종료된다(F-502) — `disconnectAll()`이 로컬 WS 서버를 닫는 것으로 구현, SSH/SQL과 동일하게 종료 후 서버측(guacd) 로그로 연결 해제 확인까지 e2e 검증 완료(단, guacd 자체의 내부 타임아웃 때문에 로그에 반영되기까지 15~20초 정도 걸림 — onegyeok 프로세스 자체는 즉시 종료됨)
- [ ] 클립보드 동기화, 드라이브 마운트, 전체화면, 수동 해상도, 자동 재연결, 지연시간 표시 — 6절 참고

## 5. 데이터 흐름 메모 (기술스택 문서 요약)

렌더러는 메인 프로세스에 `connect()`를 요청해 **로컬 WebSocket 주소 + 1회용 암호화 토큰**만 돌려받고,
실제 화면 스트림은 렌더러가 그 주소로 직접 WebSocket을 열어 받는다(IPC로 중계하지 않음 — 바이너리 화면
데이터를 IPC로 넘기면 느리고 무겁기 때문). 자세한 구조는 [기술스택 문서](../기술스택/03_RDP_기술스택.md)의
아키텍처 다이어그램 참고.

## 6. 범위 밖 (v1 이후)

- 클립보드 동기화(F-903), 로컬 드라이브 마운트(F-904)
- 수동 해상도 지정(F-902 일부), 전체화면 토글(F-906)
- 연결 끊김 자동 재연결(F-907) — 01_SSH에서 먼저 구현된 뒤 같은 패턴으로 추가
- 지연시간(ms) 표시(F-908 일부)
- `guacd` 주소/포트를 설정 화면에서 바꾸는 기능(현재 `127.0.0.1:4822` 고정)
