# VNC 기술 스택 — noVNC(RFB) 검토

> 메인 기술 스택: [00_메인_기술스택.md](./00_메인_기술스택.md) · 기능 명세: [../기능명세/06_VNC_기능명세.md](../기능명세/06_VNC_기능명세.md)
> 상태: 🔲 검토 중

- `noVNC`는 웹소켓 기반 RFB 클라이언트라, VNC 서버(TCP)와 연결하려면 TCP↔WebSocket 프록시(`websockify`)가 로컬에 떠 있어야 한다. Electron 메인 프로세스에서 이 프록시를 같이 띄우는 구조가 유력.
- 대안으로 Node 전용 RFB 클라이언트 구현체(`rfb2` 등)를 쓰면 프록시 없이 메인 프로세스에서 직접 TCP 연결이 가능 — 다만 noVNC보다 생태계가 작아 추가 조사 필요.
- [06_VNC_기능명세.md](../기능명세/06_VNC_기능명세.md) F-1003(SSH 터널링 기본 적용)과 맞물려, VNC 연결은 기본적으로 SSH 포트포워딩(`ssh2`의 로컬 포워딩 기능)을 통해 열리므로, 위 선택과 무관하게 SSH 터널 구현은 선행되어야 한다.
