# RDP 기술 스택 — 방식 미확정 (재조사 필요)

> 메인 기술 스택: [00_메인_기술스택.md](./00_메인_기술스택.md) · 기능 명세: [../기능명세/05_RDP_기능명세.md](../기능명세/05_RDP_기능명세.md)
> 상태: 🔲 검토 — 착수 시 재조사 필요

순수 JS로 RDP 프로토콜을 완성도 있게 구현한 활발한 라이브러리가 마땅치 않다. 세 가지 옵션을 검토 대상으로 남겨둔다.

| 옵션 | 설명 | 장점 | 단점 |
|---|---|---|---|
| A. `node-rdpjs` 등 순수 JS 구현 | JS만으로 RDP 클라이언트 구현 | 네이티브 빌드 불필요 | 유지보수가 저조한 패키지가 많아 리스크 큼 |
| B. FreeRDP CLI(`xfreerdp`) 서브프로세스 + 창 임베딩 | OS에 설치된 FreeRDP 바이너리를 자식 프로세스로 실행 | 검증된 구현체 재사용, 빠른 PoC 가능 | 창 임베딩(네이티브 윈도우 핸들 캡처)이 플랫폼별로 까다로움, 배포 시 FreeRDP 바이너리 동봉 필요 |
| C. FreeRDP 라이브러리를 네이티브 addon으로 바인딩 | N-API/node-gyp로 FreeRDP(C) 직접 바인딩 | 가장 견고하고 임베딩 자연스러움 | 빌드 복잡도 최고, 플랫폼별 빌드 체인 유지 부담 |

**권장**: 착수 시점에 옵션 B로 PoC를 먼저 떠서 임베딩 가능 여부를 확인하고, 안 되면 옵션 C로 전환. 지금 단계에서 확정은 보류.

연결 유지/강제 종료는 [공통 기능명세](../기능명세/00_공통_기능명세.md) F-501/502를 그대로 따른다 — 구현 시
`ssh-manager.js`/`db-manager.js`와 같은 패턴으로 `rdp-manager.js`를 만들고 `disconnectAll()`을
`main.js`의 `terminateAllSessions()`에 등록한다.
