# QA 내역

macOS(Apple Silicon) 설치 파일(`.dmg`)을 배포하고 직접 사용하면서 나온 QA 항목을 정리한 문서다.
각 항목은 **증상 → 원인 → 조치 → 확인 방법** 순서로 적었고, 상태는 ✅ 해결 / 🟡 일부 확인 / 🔲 미해결로 표시한다.

- 대상 빌드: macOS 15 이상, Apple Silicon(arm64) 전용 — 인텔 Mac은 지원하지 않는다.
- 설치 파일: [Releases](https://github.com/minaridat/onegyeok/releases) (README "Install" 참고)
- 작업 브랜치: `minaridat/mac-build`(1차), `minaridat/QA-mac`(2차) → `minaridat/integration`, `main`에 병합

## 설치 / 배포

### 1. 다운로드한 앱이 "손상되었기 때문에 열 수 없습니다" — ✅
- **증상**: `.dmg`를 받아 열면 `'onegyeok'은(는) 손상되었기 때문에 열 수 없습니다. 해당 항목을 휴지통으로 이동해야 합니다.`
- **원인**: 서명을 끄고(`identity: null`) 빌드해서 Electron 원본 서명의 봉인이 깨졌다. Apple Silicon은 유효한 서명을 최소 요건으로 보고, 다운로드(격리 표시)된 앱의 서명이 깨져 있으면 "손상됨"으로 처리한다.
- **조치**: 임시(ad-hoc) 서명으로 변경(`package.json` → `build.mac.identity: "-"`).
- **확인**: `codesign --verify --deep --strict` 통과, 격리 표시를 붙인 사본의 판정이 "손상됨"이 아니라 "서명 없는 개발자"로 바뀜.

### 2. "확인되지 않은 개발자" 경고 — 🟡
- **증상**: 서명 수정 후에도 `'onegyeok'을(를) 열 수 없음 — Apple은 악성 코드가 없음을 확인할 수 없습니다`가 뜨고 창에 열기 버튼이 없음.
- **원인**: Apple 공증(notarization)이 없는 앱에 macOS가 기본으로 띄우는 차단 창. macOS 15에서는 우클릭 → 열기로 우회되지 않는다.
- **조치(안내)**: 시스템 설정 → 개인정보 보호 및 보안 → "그래도 열기", 또는 `xattr -dr com.apple.quarantine /Applications/onegyeok.app`. README에 반영.
- **남은 것**: 경고 없이 열리게 하려면 Apple Developer ID(연 $99) 서명 + 공증이 필요하다. 사내 정책·인증서 발급이 먼저 정해져야 한다. 회사 관리 Mac(MDM)에서는 "그래도 열기"가 막힐 수 있다.

### 3. 목업·테스트용 서버가 배포 빌드에 들어 있음 — ✅
- **증상**: 설치 직후 prod-web-01, grafana-console 등 샘플 서버 12개, 데모 탭 3개, 가짜 터미널 화면이 보임.
- **원인**: 서버 목록이 `index.html`에 하드코딩된 목업 마크업이었다.
- **조치**: 샘플 서버·그룹·데모 탭·데모 pane·인스펙터 기본값·등록 폼 예시 문구(`prod-web-01`)를 모두 제거. 서버 0개, 탭 0개의 빈 화면으로 시작.
- **확인**: 앱 시작 시 서버·탭 0개, 빈 화면 활성, 서버 등록·웹 탭 열기 정상. 패키지 안 `index.html`에도 목업 이름 없음.

### 4. 서버 목록이 앱 종료 시 사라짐 (F-602) — ✅
- **증상**: 목업을 걷어내면 등록한 서버가 재실행할 때마다 없어진다.
- **원인**: 서버 목록 영속화(F-602)가 명세에만 있고 미구현이었다. 목업 서버가 항상 떠 있어서 드러나지 않았다.
- **조치**: `src/main/core/server-store.js` 신설. 서버 레코드·그룹 순서·접힌 그룹을 Electron `safeStorage`(OS 키체인 기반)로 암호화해 `userData/servers.dat`에 저장하고 부팅 시 복원. 비밀번호는 저장하지 않음. 빠른 연결 임시 서버는 저장 제외.
- **확인**: 서버 2개 등록 → 종료 → 재실행 시 그대로 복원. 파일에서 평문 검색되지 않음.
- **남은 것**: 마스터 패스워드 기반 키 파생(F-602 원안)과 유휴 잠금(F-603)은 미구현.

## SSH

### 5. 로그인 아이디가 보이지 않고 비밀번호 표시도 없음 — ✅
- **증상**: `login as:`에서 입력한 글자가 화면에 나오지 않음. 아이디는 보여야 하고, 비밀번호는 `*`로 표시되길 원함.
- **원인**: 한 줄 입력기(`createLinePrompter`)가 어떤 입력도 화면에 그리지 않았다(비밀번호처럼 숨기는 용도로만 설계).
- **조치**: 입력기에 표시 옵션 추가 — 아이디는 그대로, 비밀번호/Passphrase는 글자 수만큼 `*`. 백스페이스(한글 등 2칸 글자 포함), 방향키 이스케이프 시퀀스 처리.
- **확인**: `login as: root` 표시, 백스페이스 동작, 비밀번호 7자 → `*******`.

### 7. 첫 접속부터 터미널이 상하로 잘려 보임 — ✅
- **증상**: 분할도 안 했는데 터미널 글자가 위쪽 일부 영역(약 24줄)에만 차고 아래가 비어 있으며, 스크롤·레이아웃이 어색함.
- **원인**: `styles.css`는 `.pane`을 화면 전체에 채우는 `position:absolute; inset:0`으로 정의하는데, `ssh.css`의 `.pane-layout{position:relative}`가 이를 덮어써서 SSH 화면 높이가 내용 높이(24줄 = 376px)로 줄었다.
- **조치**: `.pane-layout{position:relative}` 삭제.
- **확인**: 패널 655px 전체 채움, 터미널 42줄. 분할(좌우) 시 양쪽 41줄.

### 8. 분할 화면에서 같은 서버 세션을 선택하면 튕김 / 열린 세션이 없으면 서버가 안 뜸 — ✅
- **증상**: 분할 pane 헤더의 선택기가 "이미 켜져 있는 세션"만 보여준다. pl-was 하나만 열려 있으면 목록에 같은 탭의 다른 pane(pl-was)만 나오고, 그걸 고르면 그 세션이 이 자리로 옮겨 오면서 분할이 합쳐져 "튕긴" 것처럼 보인다. 열린 세션이 없으면 목록이 비어서 서버를 고를 수도 없다.
- **참고**: 이 선택기와 SSH 전용 분할은 #23의 스플릿뷰로 대체되어 제거되었다.
- **원인**: 선택기가 "열린 세션 가져오기" 동작만 지원했다. 원하는 동작은 분할 후 이 pane에 **서버를 골라 새 세션을 여는 것**이다.
- **조치**: 선택기를 두 묶음으로 변경(`04_터미널분할_기능명세.md` 반영).
  - **새 세션 열기**: 등록된 SSH 서버 전부(같은 서버·이미 연결된 서버 포함). 고르면 이 pane 자리에 새 세션이 열린다.
  - **열려 있는 세션 가져오기**: 다른 탭의 세션만(같은 탭의 pane은 후보에서 제외).
  - 선택기를 열 때마다 목록을 다시 채워 서버 등록 직후에도 최신.
- **확인**: 서버 2개 등록 후 분할 → 두 pane 모두 서버 2개 표시. 같은 서버 선택 → 분할 유지 + 새 세션, 다른 서버 선택 → 해당 서버로 교체(헤더 이름 갱신), 두 탭이 열린 상태에서는 다른 탭 세션 가져오기도 동작.

## 기능 / 화면

### 6. 그룹이 없을 때 "새 그룹 추가"가 반응 없음 — ✅
- **증상**: 서버가 하나도 없는 최초 상태에서 서버 등록 창의 그룹 추가가 아무 반응이 없음. 서버 관리 탭에서 그룹을 만든 뒤에는 동작.
- **원인**: 그룹이 없으면 선택 목록의 유일한 옵션이 "+ 새 그룹 추가…"라서 이미 선택된 상태가 되어 `change` 이벤트가 발생하지 않았다.
- **조치**: 그룹이 없으면 "(그룹 없음 — 기타)" 빈 옵션을 앞에 둔다(저장 시 그룹이 비면 '기타').
- **확인**: 옵션 2개 노출, 새 그룹 입력 창이 뜨고 생성 후 선택됨.

### 9. ⌘ + `<` `>` 로 탭 이동이 안 됨 — ✅
- **증상**: 맥북에서 커맨드 키와 `<`/`>` 조합이 먹히지 않음.
- **원인**: macOS에서 `⌘`를 누르면 `e.key`가 `<`/`>`가 아니라 `,`/`.`로 오는 경우가 많아 키 값 비교로는 잡히지 않았다.
- **조치**: 물리 키(`e.code` Comma/Period + Shift)도 함께 인식. `⌘⌥,` 조합은 제외.
- **확인**: 두 탭에서 이전/다음 이동 확인(합성 키 이벤트 기준).

### 10. Web 탭 빠른 주소창 — ✅
- **요구**: 등록된 Web 서버가 없어도 Web 탭(P5)을 누르면 바로 주소를 열 수 있게.
- **조치**: 열린 Web 세션이 없을 때 빈 화면에 주소창 표시. `https://…`, `host:port`, 스킴 없는 주소를 해석. 임시 서버("빠른 연결" 그룹)로 열고 저장하지 않음.
- **확인**: `example.com` 입력 → 웹뷰로 열림("Example Domain").

### 11. SFTP 탭 빠른 SFTP/FTP/FTPS 연결 — ✅
- **요구**: 등록 없이 빠르게 SFTP/FTP 연결.
- **조치**: SFTP 탭(P2)이 비어 있을 때 전송 방식(SFTP/FTPS/FTP/FTPS implicit)·호스트·포트 폼 표시. 사용자명/비밀번호는 다음 화면에서 입력(저장 안 함).
- **확인**: FTP 127.0.0.1 → 포트 21로 접속 화면이 열림.

### 12. SQL 쿼리 결과 글자가 보이지 않음 — ✅
- **증상**: 쿼리 실행 후 결과의 글자가 하나도 안 보임. 검정색으로 바꿔 달라는 요청.
- **원인**: 공통 `.pane` 규칙의 글자색(밝은 크림색)이 SQL 화면의 색 지정보다 우선순위가 높아 흰 배경 위에 밝은 글자가 올라갔다.
- **조치**: 결과 영역을 테마와 무관하게 흰 배경 + 검정 글자로 고정(헤더·셀·안내 문구 포함).
- **확인**: 스타일 반영. (실제 DB 접속 화면은 이번 QA에서 직접 보지 못함)

### 13. RDP 화면 크기 조절 / 화면이 비어 보임 — ✅
- **증상**: 원격 화면이 창보다 작게 가운데 떠서 좌우가 비고, 전체화면에서도 비어 있음. 드래그로 크기를 조절하고 싶음.
- **원인**:
  1. 접속 시 크기를 숨겨진 영역(0×0)에서 읽어 항상 1024×768로 요청했다.
  2. RDP 화면에도 공통 패딩이 적용됐다(우선순위 문제).
  3. 크기 변경(RESIZE) 기능이 아예 구현되지 않았다.
- **조치**: pane 크기로 접속, 패딩 우선순위 수정, 동적 해상도(`disp` 채널) 구현 — 창 크기가 바뀌면 원격 해상도가 따라감. FreeRDP를 채널(drdynvc+disp) 포함으로 다시 빌드하고 소스 한 줄 패치. 구현상 함정 6가지와 근거는 [03_RDP_기술스택.md](./기술스택/03_RDP_기술스택.md) "화면 크기 조절" 참고.
- **확인**: xrdp 0.9.24 서버 대상으로 개발 실행과 패키지된 `.app` 모두에서 650 / 1122 / 782px 등으로 해상도가 따라가고 세션 유지.
- **남은 것**: **실제 Windows Server 대상은 미검증**. 클립보드·드라이브 등 다른 채널은 없다.

### 14. FTP 선택 업로드/다운로드 버튼 강조 — ✅
- **요구**: 두 버튼에 배경색을 넣고 화살표를 굵고 진하게(빨강/파랑).
- **조치**: 업로드는 파랑 배경 + 굵은 파랑 화살표, 다운로드는 빨강 배경 + 굵은 빨강 화살표.
- **확인**: 스타일 반영. (접속이 필요한 화면이라 실제 화면은 직접 보지 못함)

### 16. 최소 지원 macOS와 CPU — ✅ 결정

### 17. RDP 크기를 키우면 오른쪽·아래로 화면이 안 늘어남 — ✅
- **증상**: 13번 수정 후 창을 키우면 왼쪽 위 기존 영역만 그려지고 오른쪽·아래는 검게 비어 있음.
- **원인**: 헬퍼가 `DesktopResize`에서 `gdi_resize`를 호출하지 않고 있었다(`gdi_init()`은 이 핸들러를 등록해주지 않는다). 서버는 새 해상도로 그리는데 클라이언트 그림 버퍼는 옛 크기 그대로라 새 영역이 영원히 비었다. 줄이는 쪽은 캔버스만 작아져서 정상처럼 보였다.
- **조치**: `DesktopResize`에서 `gdi_resize`로 버퍼를 새 크기로 다시 만들고, 해상도 변경 직후 Refresh Rect(전체 재전송 요청)도 보낸다.
- **확인**: xrdp 서버에서 가로로 키움/줄임/다시 키움, 세로로 줄임/키움 후 캔버스 오른쪽·아래 끝 픽셀이 실제로 그려짐(키우기 전에는 알파 0 = 미그림이던 것이 255로 바뀜).
- **남은 것**: 실제 Windows Server 대상은 미검증.

### 18. Web 화면이 위쪽만 나오고 아래가 잘림 — ✅
- **증상**: 웹 페이지가 위쪽 약 150px만 보이고 그 아래는 검게 비어 있음.
- **원인**: `web.css`의 `.web-pane{position:relative}`가 `.pane{position:absolute;inset:0}`를 덮어써서 pane 높이가 내용 높이(툴바 + `<webview>` 기본 150px)로 줄었다. 7번(SSH)과 같은 종류의 우선순위 문제.
- **조치**: 해당 규칙 삭제(오류 오버레이는 absolute pane 기준으로 그대로 동작).
- **확인**: pane 710×655, webview 710×612로 전체를 채움.

### 19. Web 주소창 수정·북마크 — ✅
- **조치**: 주소 표시줄을 입력창으로 바꿔 크롬처럼 직접 수정하고 Enter로 이동/재연결(Esc는 되돌리기). `host:port/경로`는 포트 기준으로 http/https를 판단하고, 잘못된 주소는 빨간 테두리. `☆ 북마크` 버튼은 현재 페이지를 서버 등록 창에 채워(그룹 "북마크") 저장하게 한다. Web 보기에서는 서버 검색 아래에 `＋ Web 등록 (북마크)` 버튼이 항상 보인다.
- **확인**: 개발 앱에서 주소 변경·Enter 이동, 북마크 저장(그룹 "북마크")까지 확인.

### 20. 빠른 연결 확장 — ✅
- **조치**: SSH / SQL / RDP / VNC / SFTP·FTP / Web 모두 빈 화면에서 호스트(와 SQL 엔진·DB, FTP 방식)만 입력해 바로 연결. **호스트·포트·사용자명·비밀번호를 한 폼에서 한 번에 입력**하면 접속 화면을 거치지 않고 바로 접속한다(SSH는 터미널 비밀번호 단계에, 나머지는 접속 폼에 비밀번호를 대신 입력). 이력은 **프로토콜별 최신 5개**만 유지하고(호스트/포트/사용자명만 저장, **비밀번호는 저장 안 함**, 앱을 다시 켜도 유지) 목록과 사이드바 "빠른 연결" 그룹에서 `×`로 개별 삭제. 탭이 열려 있는 항목은 이력 정리에서 지우지 않는다.
- **주소 오타 수정**: 빠른 연결 탭 위에 주소·사용자명·비밀번호 바가 뜨고, 고쳐서 "다시 연결"을 누르면 새 값으로 다시 열고 바로 접속한다(비밀번호는 보안상 다시 입력). 연결되지 않은 옛 탭과 잘못 친 옛 이력은 같이 정리된다(Web은 자체 주소창 사용).
- **확인**: 6개 프로토콜 폼 표시, 7개 입력 시 5개만 남음, 오타 수정 후 옛 항목 제거, 삭제 후 탭 정리. 한 폼 접속은 SFTP(실제 SFTP 서버)·SSH(인증 통과까지)·SQL(MySQL)·RDP(xrdp)로 확인했다.

### 21. VNC 비밀번호 인증이 항상 실패 — ✅
- **증상**: 비밀번호가 있는 VNC 서버에서 인증이 항상 실패(Windows 빌드 작업 중 발견).
- **원인**: OpenSSL 3는 DES를 legacy provider에 두는데 `no-module` 없이 빌드하면 legacy가 별도 모듈로 빠져, libvncclient의 `OSSL_PROVIDER_load("legacy")`가 실패한다.
- **조치**: `scripts/mac/build-native-deps.sh`의 OpenSSL `Configure`에 `no-module` 추가(옵션 변경 시 다시 빌드하도록 stamp 파일 사용). RDP/VNC 헬퍼 재링크.
- **확인**: 임시 RFB 인증 서버(VNC Authentication 방식)로 올바른 비밀번호는 CONNECTED, 틀린 비밀번호는 인증 실패. 옛 빌드에서의 실패 재현은 하지 않았다.

### 23. 스플릿뷰(그룹탭) — ✅ 1차

### 25. 이전/다음 탭 단축키를 Ctrl+< / Ctrl+>로 — ✅

- **조치**: 이전/다음 탭을 **`Ctrl+<` / `Ctrl+>`(macOS는 Control 키, Windows는 Ctrl)** 로 바꿨다. Shift 유무와 상관없이 물리 키(`,` `.`)로 인식한다. 기존 `⌘<` `⌘>`, `Ctrl+Tab`, 일반 탭의 `⌘⌥←/→`도 계속 받는다. 터미널(xterm)이 키를 먼저 삼키지 않도록 capture 단계에서 처리한다. 단축키 탭·README·사이드바 안내를 같이 고쳤다.
- **확인**: CDP 키 이벤트로 Ctrl+Shift+, / Ctrl+Shift+. / Ctrl+, / Ctrl+. / ⌘+Shift+, / ⌘+Shift+. 모두 이전·다음 탭 이동 확인, 터미널에 포커스가 있는 상태에서도 동작 확인.

### 26. 탭 닫기 단축키 — ✅
- **요구**: 탭(그룹탭 포함)을 닫는 단축키.
- **발견**: 앱이 Electron 기본 메뉴를 그대로 쓰고 있어 `⌘W`(Windows `Ctrl+W`)가 "창 닫기"로 동작했다 — 탭 하나가 아니라 앱 창이 통째로 닫힌다.
- **조치**: `src/main/core/app-menu.js`에서 앱 메뉴를 직접 구성하고 `탭 > 탭 닫기`를 추가했다(macOS `⌘W`, Windows `Ctrl+Shift+W`). 활성 탭을 닫고, 그룹탭이면 그룹 전체(연결 중이면 확인 창)를 닫으며, 열린 탭이 없으면 아무 일도 하지 않는다. Windows의 `Ctrl+W`는 터미널 셸의 "단어 지우기"라서 쓰지 않았다. 새로고침/개발자 도구 메뉴는 개발 실행에서만 보인다.
- **Esc**: `Esc`는 서버 등록·수정 창, 서버 관리 화면, `⌘K` 검색창을 닫는다(단축키 탭·README 설명을 구체적으로 고침).
- **확인**: 개발 앱에서 메뉴 항목(`탭 닫기 / Cmd+W`) 실행으로 그룹탭·일반 탭 닫기와 탭이 없을 때 앱이 유지되는 것을 확인했다. 실제 키 입력(⌘W)을 OS 레벨로 눌러 보지는 못했다(자동화 권한 없음).

### 빌드 중 발견·수정한 문제

1. **FreeRDP `cmdline.c` 빈 배열(MSVC C7757)** — 정적 채널을 전부 끄면 `staticChannels[]`가 비어 MSVC가 컴파일을 거부한다(clang은 허용). 빌드 스크립트에서 맨 앞에 빈 항목을 넣고 반복문에서 건너뛰는 패치를 적용(동작 동일). `update.c` 패치는 macOS와 동일하게 적용.
2. **FreeRDP 헤더의 dllimport** — Windows에서 FreeRDP/WinPR 헤더는 정적 링크 분기 없이 `__declspec(dllimport)`로 선언한다. 헬퍼 빌드에 `FREERDP_EXPORTS`/`WINPR_EXPORTS`를 정의해 해결.
3. **VNC 비밀번호 인증 실패 (OpenSSL legacy provider)** — OpenSSL 3는 DES를 legacy provider에 두는데, `no-module` 없이 빌드하면 legacy가 별도 `legacy.dll` 모듈로 빠져 libvncclient의 `OSSL_PROVIDER_load("legacy")`가 실패 → VNC 인증(DES)이 항상 실패한다. Windows는 `no-module`을 추가해 legacy를 libcrypto에 내장. **macOS(`scripts/mac/build-native-deps.sh`)도 같은 옵션이라 같은 문제가 있을 가능성이 높다 — 비밀번호 있는 VNC 서버로 macOS 빌드 확인 필요**(지시서 규칙상 macOS 스크립트는 수정하지 않음).
4. **RDP 헬퍼 Winsock 미초기화** — libfreerdp는 `WSAStartup`을 호출자에게 맡긴다. 없으면 `127.0.0.1`도 "DNS host name was not found"로 실패. `main()`에서 Windows일 때 `WSAStartup` 호출 추가.
5. `clock_gettime` → Windows는 `GetTickCount64`. pthread/unistd는 기존 `compat.h`(91beb23) 셈 사용.

### W8. Windows에서 앱 단축키가 터미널 Ctrl 키와 충돌 — 🟡 수정, 수동 확인 필요

- **증상(코드 확인)**: macOS의 ⌘ 단축키가 Windows에서는 `ctrlKey`로 잡히는데, 전역 `document` keydown이라 xterm이 키를 터미널에 보낸 뒤에도 앱 동작이 같이 실행됐다.
  - `Ctrl+D`(셸 EOF/로그아웃) → SSH 분할, `Ctrl+Shift+D` → 가로 분할
  - `Ctrl+[`(= ESC, vim) / `Ctrl+]` → pane 포커스 이동
  - `Ctrl+K`(줄 끝까지 삭제) → 명령 팔레트, `Ctrl+I`(= Tab) → 인스펙터, `Ctrl+1~9` → 탭 전환
- **결정**: 포커스가 터미널(`.xterm`) 안에 있으면 Ctrl 단독 조합(⌘ 없이)은 앱이 가로채지 않는다 — `keyboard-shortcuts.js`의 `isTerminalCtrlKey()`, `ssh.js` 분할/pane 리스너에 적용.
  - 예외: `Ctrl+Tab`/`Ctrl+Shift+Tab`(탭 전환)은 터미널에서도 동작 — 터미널을 떠나지 않고 탭을 바꿀 수단.
  - 터미널 밖(사이드바·탭바 등을 클릭한 상태)에서는 Ctrl 단축키가 그대로 동작한다.
  - macOS의 ⌘ 단축키는 변화 없음. macOS에서도 터미널의 `Ctrl+D`가 분할을 일으키던 동작이 함께 사라진다.
- **확인할 것**: SSH 터미널에서 `Ctrl+D`가 로그아웃만 하는지, vim에서 `Ctrl+[`가 ESC로만 동작하는지, `Ctrl+Tab` 탭 전환, 터미널 밖에서 `Ctrl+K` 팔레트.
- RDP/VNC 원격 화면(canvas)에 포커스가 있을 때의 Ctrl 단축키 충돌은 이번 범위 밖(그대로).

### W10. RDP 화면 딜레이 — 🟡 수정, 실제 서버 확인 필요

- **증상**: Windows에서 RDP 접속 후 폴더·창을 끌면 화면이 한참 늦게 따라와 쓸 수 없을 정도(스플릿뷰 미사용).
- **원인 1 (가장 큼, macOS 공통)**: 헬퍼 stdout을 받는 `makeFrameReader`(rdp·vnc `helper-bridge.js`)가 64KB 조각이 올 때마다 누적 버퍼 전체를 `Buffer.concat`으로 다시 복사했다 → 수 MB짜리 화면 프레임 하나에 복사량이 제곱으로 늘어 1920×1080 한 장에 약 110ms(이 PC 실측, 초당 9장 한계). Node가 늦게 읽으면 헬퍼의 쓰기가 막히고, 같은 루프에서 처리하는 마우스·키 입력까지 밀린다.
  - **조치**: 조각은 모아 두기만 하고 프레임이 다 찼을 때 한 번만 합친다 → 같은 조건 약 6ms. 무작위 조각 경계(길이 필드가 조각 사이에 걸리는 경우 포함) 300프레임×5회로 기존과 결과 동일 확인.
- **원인 2 (macOS 공통)**: 렌더러로 프레임을 받는 대로 모두 보내서, 그리는 속도보다 빨리 오면 IPC 큐에 쌓여 지연이 커질 수 있었다.
  - **조치**: 렌더러에는 한 번에 한 프레임만 보내고(그린 뒤 `rdp:frame-ack`), 그 사이 온 프레임은 메인 프로세스의 합성 화면 캐시에 반영해 두었다가 바뀐 영역을 합쳐 한 번에 보낸다. ack가 250ms 안에 안 오면 다시 보낸다. 렌더러의 BGRA→RGBA 변환도 32비트 단위로 바꿔 1920×1080 기준 6.2ms→3.9ms.
- **원인 3 (Windows만)**: 헬퍼 연결 루프의 `Sleep(20)`이 Windows 기본 타이머 해상도(15.6ms) 때문에 실제로는 약 31ms → `timeBeginPeriod(1)`(winmm, 헬퍼 프로세스 동안만).
- **원인 4 (가장 큼, macOS 공통)**: 헬퍼 연결 루프가 `Sleep(20)` 동안 소켓을 읽지 않아 수신 버퍼가 차면 서버가 보내기를 멈췄다 → 화면 데이터가 많을 때(창 끌기) 처리량이 "버퍼 크기 / 대기 시간"에 묶여 화면이 수 초씩 밀렸다. 헬퍼 CPU 사용률은 15%로 연산 병목이 아니었다.
  - **조치**: FreeRDP 클라이언트처럼 `freerdp_get_event_handles` + `WaitForMultipleObjects`로 소켓 이벤트를 기다려 데이터가 오면 바로 처리한다(입력 큐 확인용 최대 대기 5ms). 화면 비교·전송은 16ms에 한 번.
- **실제 서버 측정** (사내 개발 서버, Windows Server, 1920×1080, 탐색기 창 제목 표시줄을 잡고 약 8.5초간 왕복으로 끈 뒤 원위치):

  | 경로 | 수정 전 | 수정 후 |
  |---|---|---|
  | 헬퍼 단독(서버→헬퍼), 끌기 멈춘 뒤 마지막 화면까지 | 3.1~4.1초 | 0.07초 |
  | 앱 전체(개발 앱 렌더러 화면), 끌기 멈춘 뒤 화면이 멈출 때까지 | 4.0초 (릴리스 v0.1.14와 같은 코드·헬퍼) | 0.08초 |

  끄는 동안 서버가 보내는 화면은 초당 30~38장, 한 장 약 2MB(창 영역). 같은 서버를 Windows 기본 원격 데스크톱(mstsc)으로 쓰면 빠른 것은, mstsc는 그래픽 파이프라인(H.264 등)을 써서 데이터가 훨씬 적기 때문이다(이 헬퍼는 rdpgfx 채널을 빌드에 넣지 않아 비트맵 갱신을 쓴다 — 개선 후보).
- **가짜 헬퍼 벤치**: 실제 RDP 서버가 이 PC에 없어(Docker·WSL 없음), 프로토콜을 흉내 내는 가짜 헬퍼(1920×1080 전체 화면을 20ms마다 전송, 첫 픽셀에 전송 시각)를 개발 앱에 붙여 화면에 보이는 픽셀의 시각으로 표시 지연을 쟀다. 수정 전 중앙값 257ms·초당 4.3장 → 수정 후 62ms·30장(최악 조건: 매 프레임 전체 화면 변경). 실제 헬퍼는 서버 없는 주소로 기동·오류 보고만 재확인.
- **macOS**: 원인 1·2는 공용 코드라 dmg도 다시 빌드하면 같이 좋아진다(헬퍼 C 코드 변경은 Windows 전용 `#ifdef`라 macOS 헬퍼 재빌드는 불필요).
